01
Cấu hình Hostname & Domain
Hostname và FQDN phải khớp với domain mail server

Hostname và FQDN ảnh hưởng trực tiếp đến uy tín server khi gửi mail. Phải cấu hình đúng trước khi cài bất kỳ thứ gì.

Kiểm tra thông tin hiện tại

Terminalbash
$ hostname # tên ngắn của server demo $ hostname -f # FQDN đầy đủ demo.akadigital.net $ ifconfig | grep "inet " inet 158.101.137.14 netmask 255.255.255.0

Sửa /etc/hostname

/etc/hostnameconfig
<short-hostname> # chỉ tên ngắn, không có dấu chấm
demo

Sửa /etc/hosts — khai báo FQDN

/etc/hostsconfig
### ADD NEW <your-server-ip> <mail-server-fqdn> <short-hostname>
158.101.137.14 demo.akadigital.net demo
⚠️
Sau khi sửa cả 2 file, chạy sudo reboot. Sau reboot kiểm tra hostname -f phải trả về đúng FQDN.

DNS A và MX cần tạo tại nhà cung cấp domain

Type Name Value Mục đích
A <mail-subdomain> <your-server-ip> Trỏ subdomain về IP server
MX @ (root domain) <mail-server-fqdn> Mail exchanger record
A: demo → 158.101.137.14  |  MX: @ → demo.akadigital.net

05
SSL / TLS
Mã hóa kết nối SMTP — bắt buộc cho production

Tạo self-signed certificate

Terminal — chạy trong thư mục config/bash
$ cd config $ openssl req -x509 -nodes -days 2190 -newkey rsa:2048 \ -keyout tls_key.pem \ -out tls_cert.pem # Khi được hỏi Common Name — điền FQDN của server: Common Name: <mail-server-fqdn>
Common Name: demo.akadigital.net

config/tls.ini

config/tls.iniini
key=config/tls_key.pem cert=config/tls_cert.pem dhparam=config/dhparam.pem # optional
✓
Production: Dùng Let's Encrypt: sudo certbot certonly --standalone -d <mail-server-fqdn> — sau đó trỏ tls.ini về /etc/letsencrypt/live/<fqdn>/privkey.pem

07
DNS Records đầy đủ
Cấu hình tại DNS manager của domain

Tất cả records cần có trước khi mail server đi vào hoạt động:

Type Name / Host Value Mục đích
A <mail-subdomain> <your-server-ip> Trỏ subdomain về IP
MX @ (root) <mail-server-fqdn> Mail exchanger
TXT @ (root) v=spf1 ip4:<your-server-ip> ~all SPF — authorize IP gửi mail
TXT <dkim-selector>._domainkey v=DKIM1; k=rsa; p=<dkim-public-key> DKIM public key
TXT _dmarc v=DMARC1; p=none; rua=mailto:<dmarc-report-email> DMARC policy
PTR <your-server-ip> <mail-server-fqdn> Reverse DNS — set tại VPS provider

TXT @ (app.unito.vn) v=spf1 ip4:131.186.43.4 ~all SPF cho app.unito.vn — IP khác

Kiểm tra DNS đã propagate

Terminalbash

08
Tạo DKIM & SPF
Chữ ký số cho email — bắt buộc để không vào spam Gmail

Bước 1 — Cài plugin và tạo key pair

Terminalbash
$ npm install haraka-plugin-dkim # Tạo private key 1024/2048-bit RSA $ openssl genrsa -out private_mail.key 1024 # Tạo public key từ private key $ openssl rsa -in private_mail.key -out public_mail.key -pubout -outform PEM # Bảo mật private key $ chmod 600 private_mail.key # Lấy public key để dán vào DNS (bỏ dòng BEGIN/END) $ grep -v "BEGIN\|END" public_mail.key | tr -d '\n'

Bước 2 — config/dkim_sign.ini

config/dkim_sign.iniini
[<your-domain>] keyfile=<path-to-private-key> # đường dẫn tuyệt đối đến private key selector=<dkim-selector> # tên selector, vd: aka, default, mail
[demo.akadigital.net]  |  keyfile=/opt/mailserver/config/private.key  |  selector=aka

Cách 2 — tạo trực tiếp bằng command

Chạy đoạn code sau để tự động tạo key ini
openssl genrsa -out private_mail.key 1024 openssl rsa -in private_mail.key -out public_mail.key -pubout -outform PEM
[demo.akadigital.net]  |  private_keyfile=/opt/mailserver/config/private_mail.key  |  public_keyfile=/opt/mailserver/config/public_mail.key

Bước cuối — DNS TXT Record DKIM

Trường Giá trị
Name / Host <dkim-selector>._domainkey.<your-domain>
Type TXT
Value v=DKIM1; k=rsa; p=<dkim-public-key>
aka._domainkey.demo.akadigital.net → v=DKIM1; k=rsa; p=MIGfMA0GCSqGSIb3DQEBAQUAA4GN...
🔍
Kiểm tra DKIM tại mxtoolbox.com/dkim.aspx — nhập domain và selector. Kết quả "DKIM Record Found" là thành công.

PM2 — Process Manager
Giữ Haraka luôn chạy, tự restart khi crash
Terminalbash
$ sudo npm install pm2 -g # Khởi động Haraka qua PM2 $ pm2 start haraka.js --name "mailserver" # Tự start khi reboot $ sudo pm2 startup && sudo pm2 save # Lệnh thường dùng $ pm2 status # xem tất cả process $ pm2 logs mailserver # log realtime $ pm2 restart mailserver $ pm2 stop mailserver

Plugin API gửi mail
HTTP API gửi mail qua Haraka — 2 cách triển khai

Tạo file plugins/sendMail.js và khai báo tên file trong config/plugins. Plugin expose HTTP API POST tại port 5000.

Gọi API — ví dụ request body

Nodemailer transporter với DKIM signing

plugins/sendMail.js — nodemailer configjavascript
const transporter = nodemailer.createTransport({ host: 'localhost', port: 25, secure: false, auth: { user: '<mail-username>', pass: '<mail-password>' }, tls: { rejectUnauthorized: false }, dkim: { domainName: '<your-domain>', keySelector: '<dkim-selector>', privateKey: fs.readFileSync('<path-to-private-key>') } });

14
Troubleshooting thường gặp
Debug log và xử lý lỗi phổ biến

Xem log Haraka

Terminalbash
$ pm2 logs mailserver # log realtime $ pm2 logs mailserver | grep -i "error\|bounce" # chỉ lỗi $ pm2 logs mailserver | grep -i "delivered" # gửi thành công
✕ Mail vào spam Gmail / dkim=fail trong header
Kiểm tra DNS: dig TXT <selector>._domainkey.<your-domain>
Đảm bảo selector trong dkim_sign.ini khớp với tên trong DNS (vd: selector=aka → DNS name: aka._domainkey)
Kiểm tra đường dẫn private key trong config có đúng không.
✕ Connection refused port 25
sudo netstat -tulpn | grep 25 — Haraka có đang listen không?
pm2 status — process còn sống không?
Kiểm tra Security Group/Firewall tại VPS provider đã mở port 25. AWS, GCP mặc định block port 25.
✕ 550 5.7.1 — IP bị blacklist
Kiểm tra tại mxtoolbox.com/blacklists.aspx với <your-server-ip>
Request delist tại Spamhaus: www.spamhaus.org/removal/
✕ Authentication failed khi gửi mail
Kiểm tra username/password trong config/auth_flat_file.ini
Thêm flag -v vào lệnh swaks để xem chi tiết quá trình auth.
✕ Mail stuck trong queue
ls -la ./queue/ — xem file đang đợi
pm2 logs mailserver | grep "temp fail\|bounce" — xem lý do fail
MX record của domain nhận có thể không resolve — kiểm tra dig MX gmail.com
